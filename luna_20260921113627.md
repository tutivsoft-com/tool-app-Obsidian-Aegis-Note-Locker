# Store-readiness audit — Aegis Note Locker

Audit date: 2026-09-21

## Classification and score

- Classification: real public Obsidian community plugin; not a conventional mobile/desktop app-store package.
- Score: 80/100.
- Confidence: high.
- Current status: version 3.3.12 offline-first plugin with local AES-256-GCM note/frontmatter protection, preview/verify/staged writes, conflict checks, encrypted backup export, undo/rollback, bulk locking, session timeout, optional central billing, privacy documentation, threat model, user guide, and release-attestation workflow.

## Git and size evidence

- Branch: `main`; clean worktree; 18 commits; latest observed commit `936433a` on 2026-09-21.
- Meaningful LOC: approximately 2,507 across 14 tracked production JS/TS/CSS files. Method: production source/UI only; excludes docs, tests, generated/dependency/build/media content.
- Evidence: `manifest.json`, `src/crypto.ts`, `src/safety.ts`, `src/frontmatter.ts`, `src/ui.ts`, `src/billing.ts`, `README.md`, `docs/PRIVACY.md`, `docs/THREAT_MODEL.md`, and `.github/workflows/release-attestation.yml`.

## Findings

- The security model is thoughtfully documented and includes authenticated encryption, random salt/nonce, test decrypt before replacement, conflict detection, and explicit recovery limitations.
- No automated test suite is tracked. Crypto envelope compatibility, malformed/corrupt notes, frontmatter preservation, cancellation, concurrent edits, rollback, session timeout, and billing failure states need regression coverage.
- Encryption is password-based and recovery depends on the user’s password/backup workflow; the UI and listing must make loss-of-password/data-recovery limits unmistakable.
- Optional billing/network calls must stay content-minimal and synchronized with the privacy/threat-model documentation. Keep public release bundles free of credentials and stale build outputs.

## Distribution readiness

- Package: validate clean Obsidian release assets, manifest version, minimum Obsidian version, GitHub release attestation, and upgrade migration behavior.
- Listing: provide current screenshots/GIFs for lock/unlock, preview, backup, bulk progress, and recovery warnings; keep privacy/threat-model and support links public and versioned.
- Age rating: not applicable to a conventional store; Obsidian community-plugin policy and encryption/privacy disclosures apply.
- Monetization: optional one-time/credit billing needs clear free-use, paid-use, offline, refund, and failed-charge semantics without ever sending note content.

## Priority actions

1. Add crypto/property-based and destructive-workflow tests.
2. Add a clean-build/package verification step for the public release zone and version parity.
3. Reconfirm privacy/billing payloads and recovery warnings before the next public release.
